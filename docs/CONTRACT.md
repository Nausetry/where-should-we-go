# Build contract

Source of truth for requirements: `docs/PRD.md`. This file fixes the interfaces so several builders can work in parallel without colliding. Where this file is more specific than the PRD, this file wins. Where they disagree on intent, the PRD wins and the disagreement goes in `docs/DEVIATIONS.md`.

## 0. Ground rules

- American English. No em dashes in any visible text or docs. Plain business wording, no system terms in the UI.
- Static site, no build step. Plain ES modules. `@supabase/supabase-js` is loaded from `https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2.49.4/+esm` (builders verify the version resolves and pin the working one). Serif font from Google Fonts with a Georgia fallback.
- Secrets: `.env` is git-ignored and holds the project URL, publishable key, secret key, service-role key, and database password. Load it with `set -a; source .env; set +a`. Never print secret values, never commit them, never put them in the page. `config.js` (committed) holds only the URL and publishable key.
- Test trips created in the hosted project are named with the prefix `ZZ-TEST ` and are deleted by the test that created them.
- Builders do not run `git commit` or `git push`. The integrator commits. Builders do not edit files owned by another builder. If a builder needs a change in another's file, it writes the request to `docs/REQUESTS.md` (append only).
- Hosted database changes go through files in `supabase/migrations/` and `npx supabase db push` (password from `.env` as `SUPABASE_DB_PASSWORD`). Never edit the hosted schema by hand.
- Do not touch the three other Supabase projects or any other GitHub repository.

## 2. Release 1 database

Postgres on Supabase. All objects in schema `public`. Every table has RLS enabled in migration 0001 with permissive policies for `anon` and `authenticated` (Release 1 is open by decision D4). Release 2 replaces them.

### Tables

`trips`: `id text primary key` (8 characters from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, enforced by check, generated by `create_trip`), `name` (3 to 60 after trim), `destination` (2 to 60), `start_date date`, `end_date date` (>= start), `itinerary_size int` (1 to 30), `voting_deadline timestamptz not null`, `status text default 'open'` (`open` or `closed`), `closed_at timestamptz`, `default_activity_id uuid` (foreign key to activities, on delete set null), `created_by uuid null` (Release 2), `created_at timestamptz default now()`.

`activities`: `id uuid default gen_random_uuid()`, `seq bigint generated always as identity` (the "added earliest" tie-break), `trip_id` (cascade), `title` (3 to 80), `description` (null or up to 140), `source_url` (null or `^https?://[^[:space:]]+$`, up to 500), `created_at default clock_timestamp()`. Unique `(id, trip_id)`.

`members`: primary key `(trip_id, voter)`, `voter text` (8 to 64 characters), `display_name` (2 to 40), `role` (`organizer` or `member`, default `member`), `email text null`, `joined_at`. In Release 1 `voter` is a browser-generated id and a person becomes a member by entering a name. In Release 2 `voter` is `auth.uid()::text`.

`votes`: `id uuid`, `trip_id`, `activity_id`, `voter`, `created_at`. Unique `(activity_id, voter)`. Foreign keys: `(activity_id, trip_id)` to activities on delete cascade, and `(trip_id, voter)` to members on delete cascade (removing a member removes their votes).

`invites` (Release 2): `(trip_id, email)` unique, email stored lowercase, `role`.

All text columns reject control characters (`[[:cntrl:]]`) and are checked trimmed.

### Effective status

A trip is effectively closed when `status = 'closed'` or `now() >= voting_deadline`. A function `trip_is_closed(trip_id)` implements this. Triggers raise exception `voting_closed` on any insert, update, or delete on `votes` and `activities` of a closed trip, and `too_many_activities` past 30 activities. No deadline job exists; the view computes status on read.

### Decision rule (PRD section 5), implemented once in views

For a trip:
- Members are rows in `members`. A member with zero votes is a non-voter.
- Effective default pick = `default_activity_id` if it still exists, otherwise the activity with the lowest `seq`.
- Default votes exist only when the trip is effectively closed. Each non-voter adds one default vote to the effective default pick. Before close, default votes are 0.
- Rank by `total_votes` descending, then the default pick first, then lowest `seq`.
- `in_itinerary` is true for the first `itinerary_size` ranked activities.
- `tie_broken` is true when any two activities with different ranks-by-rule share the same total at the boundary of the itinerary.

### Views (granted `select` to anon, authenticated; `security_invoker = true`)

`trip_summary`: `trip_id, name, destination, start_date, end_date, day_count, itinerary_size, voting_deadline, status, effective_status ('open' or 'closed'), closed_at, member_count, voted_count, not_voted_count, cast_votes_total, default_votes_total, activity_count, tie_broken, default_activity_id (effective), as_of (now())`.

`trip_standing`: `trip_id, activity_id, seq, title, description, source_url, rank, cast_votes, default_votes, total_votes, is_default_pick, in_itinerary`.

`trip_voters`: `trip_id, activity_id, voter, display_name, voted_at`.

`trip_members`: `trip_id, voter, display_name, role, joined_at, has_voted`.

### Functions (security definer, `set search_path = public`, execute granted to anon and authenticated in Release 1)

Errors are raised as exceptions whose message begins with a code from section 5, optionally followed by `: detail`.

| Function | Returns | Behavior |
|---|---|---|
| `create_trip(p jsonb)` | `text` (trip id) | `p` = `{name, destination, start_date, end_date, voting_deadline, itinerary_size, organizer_name, voter, activities:[{title, description, source_url}]}`. Validates everything (`invalid_input: <field>`), requires deadline in the future (`deadline_passed`), 3 to 10 activities, generates a unique id, inserts trip, activities, and the creator as an `organizer` member, sets the first activity as default pick. One transaction, all or nothing. |
| `join_trip(p_trip text, p_voter text, p_name text)` | void | Upserts a member. `trip_not_found` if unknown. Allowed when closed (name only). |
| `set_vote(p_trip text, p_activity uuid, p_voter text, p_on boolean)` | void | Inserts or deletes the vote. `not_a_member`, `voting_closed`, `activity_not_found`. Idempotent. |
| `add_activity(p_trip text, p jsonb)` | `uuid` | `{title, description, source_url}`. |
| `update_activity(p_activity uuid, p jsonb)` | void | |
| `remove_activity(p_activity uuid)` | `int` (votes removed) | If it was the default pick, the default falls to the earliest remaining. |
| `update_trip(p_trip text, p jsonb)` | void | Any of name, destination, start_date, end_date, voting_deadline, itinerary_size. Re-validates. Blocked when closed except through `reopen_trip`. |
| `set_default_pick(p_trip text, p_activity uuid)` | void | |
| `close_trip(p_trip text)` | void | Sets status closed, `closed_at = now()`. |
| `reopen_trip(p_trip text, p_deadline timestamptz default null)` | void | Sets status open and clears `closed_at`. If the stored deadline has passed, `p_deadline` is required and must be in the future (`deadline_passed`). |
| `delete_trip(p_trip text, p_confirm_name text)` | `jsonb` `{activities, votes, members}` removed | Requires exact name match (`name_mismatch`). |

### Realtime

`votes`, `activities`, `members`, `trips` are added to the `supabase_realtime` publication with `replica identity full`.

### Local test harness

`tests/prelude.sql` defines what Supabase provides that PGlite lacks: roles `anon`, `authenticated`, `service_role`; schema `auth` with `auth.users(id uuid, email text)` and `auth.uid()` / `auth.email()` reading `request.jwt.claim.sub` and `request.jwt.claim.email`; an empty publication `supabase_realtime`. `tests/db.js` exports `freshDb()` which applies the prelude and then every migration in order, plus helpers `asRole(db, role, claims)` to run statements as a role.

## 3. Client modules (interfaces the views builder and foundation builder share)

### `js/api.js` (Foundation)

All functions return promises and throw `ApiError` (`error.code` is one of section 5, `error.message` is plain wording for the screen). Views call only these, never the database directly.

```
export class ApiError extends Error { code; detail }
export function getVoterId()                 // random id in localStorage, memory fallback
export function getSavedName()               // name saved in localStorage or ''
export function saveName(name)
export async function createTrip(input)      // input per create_trip + voter; returns { id }
export async function loadTrip(id)           // { summary, standing, voters, members, me } or null if not found
                                             // me = { isMember, name, role, votedActivityIds:[...] }
export async function joinTrip(id, name)
export async function setVote(id, activityId, on)
export async function addActivity(id, a)     // returns activity id
export async function updateActivity(activityId, a)
export async function removeActivity(activityId)   // returns { votesRemoved }
export async function updateTrip(id, fields)
export async function setDefaultPick(id, activityId)
export async function closeTrip(id)
export async function reopenTrip(id, deadlineIso)
export async function deleteTrip(id, confirmName)  // returns { activities, votes, members }
export function subscribe(id, onChange)      // returns unsubscribe; onChange() fires on any change; silent reconnect; also fires on tab focus
```

Release 2 changes only the inside of these functions (and adds sign-in functions listed in the Release 2 contract). Signatures above stay stable.

### `js/state.js`, `js/ui.js`, `js/app.js`, `js/views/*` (Views)

Routing: bare URL is the create screen; `?trip=CODE` is the trip screen. Unknown code shows "No trip found for this link. Check the code and try again." The page title and heading are set from trip data.

## 4. Screens and test hooks

The test builder writes specs against these `data-testid` values and visible labels before the UI exists. The views builder must implement them exactly. Anything a test needs that is missing goes into `docs/REQUESTS.md`.

### Create screen (step 1, form)

Inputs: `trip-name`, `destination`, `start-date` (type date), `end-date` (type date), `voting-deadline` (type datetime-local, label states the time zone), `itinerary-size` (number, no default, helper text shows the activity count), `organizer-name`. Activity rows, indexed from 0: `activity-title-N`, `activity-description-N` (with `counter-activity-description-N`), `activity-source-N`. Three rows at start. `add-activity-row` adds one (max 10). `remove-activity-row-N` removes one (min 3 enforced with message). Primary action `review-button` labeled "Review trip". Errors: `error-summary` at top listing all errors, and `error-<fieldid>` beside each field, where fieldid is the testid above. Field labels show "Required" or "Optional" and an example. The typed values stay after an error.

### Create screen (step 2, read-back)

`review-summary` lists every entered value with units (for example "6 activities", "5 days"). `review-edit` goes back with values intact. `create-confirm` labeled "Create trip" (the one red item). Double presses create one trip. On success: `trip-link` (full URL text), `copy-link` ("Copy link"), `open-trip` ("Open trip").

### Trip screen

Header: `trip-title`, `trip-destination`, `trip-dates`, `trip-deadline` (red while open), `trip-status` ("Voting open" or "Voting closed"), `standing-asof` ("Standing as of ..."), `rule-text` (the plain-words paragraph), `not-voted-note` ("N of M members have not voted. The default pick counts once for each at close." shown while open), `caveat-text` (Release 1 only: anyone with the link can vote, edit, and delete).

Joining: before a person's first vote, `join-name` (display name input) and `join-submit` ("Save name and continue"). After that the name shows as `me-name`.

Each activity has `activity-<id>`, `activity-title-<id>`, `activity-description-<id>`, `activity-source-<id>`, `votecount-<id>` ("7 votes"), `vote-<id>` (a button with `aria-pressed`; label "Vote" or "Withdraw vote"), `who-<id>` ("Show who voted") and `voters-<id>` (names with times), and `default-badge-<id>` text "Default pick" on the default pick.

Organizer actions (Release 1: visible to everyone): `add-activity-title`, `add-activity-description`, `add-activity-source`, `add-activity-submit`; per activity `edit-<id>`, `remove-<id>`, `set-default-<id>`; `itinerary-size-input` and `itinerary-size-save`; `close-voting`; `reopen-voting`; `delete-trip`.

Confirmation dialogs (native `dialog`): `confirm-dialog`, `confirm-consequence` (states numbers), `confirm-input` (delete only), `confirm-ok`, `confirm-cancel`.

Confirmed state: `itinerary-table` (columns Rank, Activity, Cast votes, Default votes, Total), `confirmed-statement` ("Itinerary confirmed", red, with date), `basis-line` ("9 members, 14 cast votes, 4 default votes" plus tie or no-vote notices).

### One red item per screen

Create form: `review-button`. Create read-back: `create-confirm`. Trip, open: `trip-deadline`. Trip, closed: `confirmed-statement`. Release 2: sign-in screen `signin-submit`; not-invited `notinvited-text`; members `add-members-button`. Accent color `#8B1A1A`, applied through the CSS class `.accent`. No other element may use it (text, background, or border).

## 5. Error codes

`invalid_input`, `deadline_passed`, `trip_not_found`, `not_a_member`, `voting_closed`, `activity_not_found`, `too_many_activities`, `name_mismatch`, `not_signed_in`, `not_invited`, `not_organizer`, `last_organizer`, `already_claimed`, `network`. `api.js` maps each to plain wording, for example `voting_closed`: "Voting closed at <time>. Your vote was not recorded."

## 6. Design checks the tests enforce (PRD section 9)

On every screen at 1280 and 390 pixel widths: at most one element uses `#8B1A1A`; no element has a box-shadow, a vertical border, a gradient, or a background color other than white (table rows and inputs included); no `img`, `svg`, or `canvas`; no emoji or pictographic characters in text; body font family resolves to a serif; numeric cells use tabular lining figures; focus outline is solid and visible; tap targets at least 44 pixels; text contrast meets WCAG AA; no `innerHTML` assignment with user text (grep check).

## 7. Release 2 contract (added in the second build)

Sign-in by email with a link and a code in one message; `members.voter = auth.uid()::text`; RLS policies on every table by membership and role; `join_trip(p_trip)` uses the signed-in user and invite; `claim_preview(p_trip)` and `claim_trip(p_trip)`; `trip_access(p_trip)` returns `member`, `invited`, or `none` without leaking data; roles changed by organizers with at least one organizer kept; `create_trip` requires sign-in. Detailed signatures are written by the Release 2 DB builder into `docs/CONTRACT_R2.md` before the views are built.
